fix(scrapers): accept a report-only collector instead of failing every sweep

PublicNoticesEmailScraper is registered in realScrapers, but its scrapeFeed
ingests its own evidence and returns a run report — { accepted, rejected,
evidencePackets, publicationStatus, report } — never an array of listing
rows. The scheduler only understood the listing shape, so
scheduler.js:224 threw "returned a non-array payload" for it on every sweep.

The failure was contained: mapWithConcurrency wraps each item, so the other
23 sources ran and this one was merely recorded as rejected. But the source
could never succeed, it lost a worker slot every cycle, and it logged a
spurious error on every run. It is also not a BaseScraper, so it has no
getRawPublisherRecord — which is why the new interface validator flagged it
as the single non-conforming adapter out of 24.

A collector has two legitimate shapes at this seam: a listing collector that
returns records, and a report-only collector that ingests its own evidence
and reports counts. The scheduler now recognises the second as an outcome
rather than a malformed payload, records its counts, and ingests an empty
listing set. The non-array throw remains for payloads that are neither.

Two downstream reads had to change with it. `items.length` is undefined for a
run report, so `finishRun` would have been handed `discovered: undefined` and
the completion log would have printed "NaN rejected". Both now read the
normalised list.

Also fixed: catalog-adapter-join.test.js inferred "scheduled scraper" from
`require('./name')` in the scheduler, so the new scraper-interface helper read
as a scraper named "scraper-interface". Matching scrapeFeed( in file text did
not help, because a comment in that file mentions scrapeFeed(). It now loads
each module and checks whether it actually provides something callable at the
scraper interface, which excludes every support module in that directory
without a hand-kept list that would rot when the next helper lands beside
them.

test/scrapers/report-only-collector.test.js (5 tests) covers the report-only
shape end to end, including that PublicNoticesEmailScraper.scrapeFeed really
does return a non-array, and that no NaN or undefined reaches the counts.
Validated by reverting the fix and confirming the guard failed on the exact
assertion.

Verified: all 17 test:* runners exit 0, tsc --noEmit clean, verify:gate green.
