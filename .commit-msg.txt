test: wire 91 orphaned test files into runners and guard against new ones

Root cause found while auditing the a58f76f merge: 91 test files in test/ were
referenced by no package.json runner. They were not failing — they were never
executed, so they could never fail and provided no protection. That is exactly
why four working /api/source-network routes could be deleted in the same merge
without any signal.

Of 93 files audited, 91 passed green and are now running. The two that did not:

- test/property-title.test.js — its 5 failures are live PropertyTitle API calls
  needing external credentials, so it cannot run in CI. Now an explicit,
  reasoned exemption rather than a silent omission.
- test/context.test.js — was genuinely stale: CONTEXT.md had not been
  regenerated, because the check that would have caught it was itself
  unwired. Regenerated.

Wired into existing runners:
  test:sources         27 files (robots, access policy, publisher gallery,
                       live contracts, cadastre, sync/seed/delta, scrapling)
  test:ai               3 files
  test:intelligence    18 files
  test:evidence-truth  18 files (routes, security, CSP, production env/proxy,
                       evidence, enrichment gateway, image isolation)

New runners for clusters that had no home:
  test:documents       7 files (document review store/route/transitions)
  test:media           4 files (mapillary, panoramax, provider cache, street view)
  test:workspace       4 files (flows, mutation gate, readiness, session)
  test:ops            11 files (telemetry, skills doctor, coordinator, coverage
                       matrix, form submissions, listing history, db-unreachable,
                       record groups, onboarding budget, context drift)

test/test-wiring.test.js now fails the build if any test file is unreachable
from a runner, or if an ALLOW_UNWIRED exemption goes stale. Verified by planting
a throwaway orphan and confirming the guard failed with that exact filename,
then removing it and confirming green. A guard that has never been seen to fail
is not evidence of anything.

.dockerignore: a58f76f dropped `artifacts`, `test-results`, `playwright-report`
and `.next-*` while keeping only `.next/`. artifacts/ is git-tracked (6 files,
1.5 MB of walkthrough screenshots plus a .webm) and `.next-verify/` is 31.7 MB;
with `COPY . .` in the runner stage both were being copied into the production
image. Restored all four patterns. The commit's genuine security additions
(.secrets/, *.pem, *.key, .env) are kept.

CONTEXT.md regenerated — its digest covers package.json scripts, so wiring the
new runners invalidated it, as documented in the generated header.

All 16 test:* runners exit 0. tsc --noEmit clean. verify:gate green.
