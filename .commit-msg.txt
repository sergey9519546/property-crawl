docs(env): document the operator-actionable crawler safety switches

Code reads 178 environment variables. .env.example listed 82. The 99-variable
gap is mostly benign - OS variables like TEMP, local store-path overrides,
test-only ports - but a subset of it was not, and it was the subset that
mattered: switches that change safety or write behaviour.

The clearest case is one the code already complained about. The GSA adapter
refuses to crawl a catalog-declared robots exclusion, and its own error message
names the variable to set:

  Refusing to crawl https://realestatesales.gov/our-listing: catalog-declared
  robots exclusion. Set SCRAPER_RESPECT_ROBOTS=0 to override (operator-only).

The source catalog notes repeat the name. The code told the operator exactly
which knob to turn, and .env.example did not list it - so an operator who hit
the refusal had no way to discover the override except reading source.

Now documented, with the defaults read from the actual call sites rather than
assumed:

  SCRAPER_RESPECT_ROBOTS     refuse catalog robots exclusions unless =0
  SCRAPLING_LIVE_WRITE       enrichment gateway is read-only until opted in
  RUN_REAL_SCRAPERS          set to 0 to stop scheduled outbound collection
  WORKSPACE_COOKIE_INSECURE  dev-only; a non-Secure cookie is sent in cleartext
  SCRAPE_INTERVAL_HOURS      recurring ingestion cadence, default 6
  UNBROWSE_PACKAGE_ROOT      unbrowse tooling install root
  UNBROWSE_CONFIG_DIR        unbrowse consent directory
  PROPERTY_TITLE_*           optional title client (unset = unavailable)
  ZILLOW_MCP_*               optional Zillow client (unset = unavailable)

SCRAPER_RESPECT_ROBOTS is shown as =1 and never as =0, because 0 is the
operator override that disables a publisher-declared restriction, not a
default. A test pins that direction.

Scope is deliberately limited to the safety- and write-relevant subset.
Documenting all 99 would bury the switches that matter and would encode
assumptions about variables that are fine to leave implicit.

test/env-docs.test.js (6 tests) pins the subset plus three content
assertions: the robots example must not present 0 as the default, the cookie
escape hatch must be flagged as cleartext/dev-only, and the live-write opt-in
must be described as read-only by default. Validated by stashing .env.example
- the test failed naming all four missing safety switches, then passed restored.
