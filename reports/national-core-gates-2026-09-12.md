## GSA access and identity gap

The current adapter targets the anonymous public index `https://realestatesales.gov/our-listing` and sequentially follows `/asset-details/?property_id=<digits>` links. This audit deliberately did not make a live request, so present-day accessibility, response shape, and challenge behavior remain unverified.

The identity parser accepts a bounded alphanumeric sale number, then a case number, then falls back to the numeric `property_id`. It correctly rejects adjacent prose such as `Sale Number: Block 3 is offered separately` and preserves the rejected candidate in provenance. The unresolved point is durability: `property_id` is a site routing key, and the repository contains no publisher statement or cross-run proof that it remains stable when a property is relisted or the site is rebuilt. A future canary should report counts by `identityBasis` and compare prior exact source URLs before treating fallback identities as durable joins.
