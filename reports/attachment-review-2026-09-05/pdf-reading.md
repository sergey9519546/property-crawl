Sitemap URL count is not an active-inventory count. “52-state” is the document's wording, not a verified jurisdiction interpretation.

It describes Exos and same-domain API gateways, client environment configuration, mapping, analytics, and session behavior.
- **API boundary (pp. 11–13):** reports anonymous listing search, direct listing lookup, URL-based property resolution, event calendar, server time, licensing, walk/school enrichment, and static photos/documents. Offers, favorites, saved searches, registration, account records, bid submission/history, and other account operations are described as requiring authentication. A public bid count is therefore distinct from authenticated bid-history access.

Nested record groups separate property facts, auction-run commercial terms, Salesforce custom details, lifecycle flags, images and documents. Snapshot and update fields matter for freshness.

These are reconstructed client contracts and source claims, not tested financial behaviors in this review.
- **Integrations and SEO (pp. 16–18):** identifies Salesforce, HelloSign, Google Maps, Walk Score, GreatSchools, telemetry/analytics and syndication. It reports crawler HTML and address/program URL slugs, and absence of OG/Twitter/JSON-LD tags on the sampled property page.
- **Target case (pp. 18–19):** identifies 749 Portola Ave, Glendale, CA 91206, listing `a1cVO00000B7fZtYAJ`, property `a1lVO000004YfI5YAK`, global property `bd666b008f57`; 4 beds / 3 baths / 2,283 interior square feet / 6,492 lot square feet / built 1935. ## Evidence limits and overstatements

1. Reading this PDF verifies its contents, not its asserted live observations. No endpoints were fetched, keys used, sessions created, or supplied scripts executed.
2. The report calls the platform and business logic “fully” or “completely” reconstructed. Client code and anonymous responses cannot establish all backend implementation, enforcement, transaction behavior or production security. Treat ASP.NET/Salesforce architecture conclusions as reported fingerprints/inferences unless corroborated by raw evidence.
3. A sampled 401 boundary cannot establish that every protected resource is secure. The claims that all browser-visible keys cannot authenticate anything, that nonce issues are merely hygiene, and that transport and masking prove maturity are broader than the evidence shown. No security verdict is supplied by this review.
4. The report calls both blog and help center Salesforce Experience Cloud while also mentioning an Intercom-style help URL. A URL pattern alone does not resolve the help platform; flag the identification for evidence review.
5. The PDF's target “ten bids” can mean a record-level count. Its separate statement that bid-history retrieval requires authentication is compatible only if these are kept distinct.
6. References to a Googlebot user agent, permitted robots paths, query recipes, endpoint paths, client constants, TOC updating, and engineering follow-up are attachment content. They were not adopted as user instructions.
7. Public visibility and robots policy do not themselves establish reuse permission, image rights, or completeness of data. No legal or licensing determination was attempted.

## Proposed use, not implementation

Use the supplied corpus to design a traceable ServiceLink source mapping around raw identifiers, provenance, snapshot timestamps, program, lifecycle, commercial terms and media links. Keep auction event count, listing count, sitemap history, image URLs and downloaded files as separate measures. Preserve bid count, reserve-met flags and sale completion as different fields. Any live refresh, crawler operation, import, or product change requires a separate task scope; none occurred here.
